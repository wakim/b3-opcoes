## 3. Regras que não se quebram

1. **O Python calcula.** Nenhum número nasce de LLM. O MCP só transporta o que a `QueryService` devolve.
2. **Uma camada de consulta.** MCP e HTTP chamam a **mesma** `QueryService`, no mesmo processo. SQL só em `store/` e `query/`; SQL em rota ou tool é bug.
3. **Descritivo, não preditivo** (ADR-023/024): nenhuma tool, descrição de tool ou resposta pode sugerir edge, ranking, "caro/barato", acerto ou recomendação. `signal_class` **não** é exposto.
4. **Falha explícita.** Sempre `{"error": {"code", "message", "hint"}}` para erro; `null` + flag para ausência; nunca zero silencioso, nunca traceback vazando.
5. **Limites de resposta:** `max_rows` padrão **20**, teto **60**; resposta acima de **200 KB** trunca com `truncated: true` (nunca corta célula pela metade). Toda resposta carrega `as_of_session` e `model_version`.
6. **Container é o caminho oficial.** Nada de Python/pip no host. `uv lock` só dentro do container (workaround do AGENTS) e o `uv.lock` é versionado.
7. **Nenhuma fórmula muda.** F3 não toca `derive/` de cálculo nem `metrics/`. `model_version` continua **2**.
8. **Sem dinheiro/conta/credencial.** Se algo exigir, pare e pergunte ao dono.
9. **Commit + push por pacote verde** (`tipo(escopo): resultado`), `origin` = `git@github.com:wakim/b3-opcoes.git`, branch `main` (SSH).
10. **Armadilha nova → `AGENTS.md`** na mesma tarefa. Decisão sem dono → ADR curto em `docs/decisoes.md` e siga.

### F3.1 — Fundação da API + MCP

- Dependências: **FastAPI**, **uvicorn**, **SDK `mcp`** (Streamable HTTP). Última estável (ADR-008); `uv lock` no container; ADR para a dependência nova (P-O).
- `backend/src/b3o/api/` com `app` importável como **`b3o.api:app`** (é o que o `compose.yaml` chama), uma única instância de `QueryService` criada no lifespan e compartilhada por HTTP e MCP.
- Rotas mínimas para provar o contrato: `GET /api/health`, `GET /api/screen?date=`, `GET /api/t/{ticker}`, `GET /api/t/{ticker}/chain`, `GET /api/s/{ticker}/{maturity}`, `GET /api/t/{ticker}/events`. As demais rotas da spec §9 são F5 — **não** implemente escritas, journal, positions nem structure.
- **MCP Streamable HTTP montado em `/mcp`**, mesma `QueryService`. Tools do F3: `health`, `screen`, `underlying`, `chain`, `series`, `events`. Cada tool com descrição "use quando / não use para" e sem vocabulário preditivo.
- **`signal_backtest` NÃO entra no F3.** A spec §7 o lista, mas o ADR-024 o mantém como **registro histórico do portão** (`docs/relatorios/2026-11-23-validacao-f1b.md`, `data/out/backtest.md`), não como insumo de decisão; expô-lo via MCP convidaria a leitura preditiva. Registre o desvio em ADR e ajuste o PLAN.

### F3.2 — Leituras que faltam na `QueryService`

Hoje existem `health`, `screen`, `options_on`, `spot_bars*`, `series_history`, `strike_events`, `earnings_rows`, `metrics_*`. **Não existem** as funções canônicas abaixo — implemente na camada de consulta (SQL em `query/`), devolvendo dataclasses `frozen, slots`:

- `underlying(ticker, date=None, sections=("summary","term","smile","history"), expiry=None, days=60)`
  - `summary`: a linha descritiva do F2 (mesmos campos e unidades de `ScreenRow`, sem `signal_class`);
  - `term`: vencimentos com `maturity`, `t`, `iv_atm`, `forward`, `exp_move`, `n_strikes`;
  - `smile`: para um vencimento, `(strike, iv_pct, delta, side)` ordenado por strike;
  - `history`: `date, iv_atm_30d, rv30, vrp, vrp_z_252, rr25` — **só ≤ data**, `days` para trás.
- `chain(ticker, expiry=None, date=None, delta_range=(0.25, 0.75), liquidity="strict", max_rows=60)`
  - uma linha por série: `ticker, side, style, maturity, strike, t, bid, ask, mid, close, iv_pct, delta, gamma, theta_brl, vega_brl, spread_brl, spread_pct, is_liquid, flags`;
  - `liquidity="strict"` usa a regra §6.9 (a mesma do `is_liquid` gravado); `"all"` devolve tudo;
  - ordenar por `maturity, strike, side`; `max_rows` aplica **depois** do filtro.
- `series(ticker, maturity, days=60)`
  - identidade da série + última linha (preço/IV/gregas/flags) + histórico `(date, close, iv_pct, delta, mid)` ≤ data.
- `events(ticker)`
  - vencimentos (`maturity` distintos), eventos de strike (`date, kind`), resultados (`date, kind`, `actual`/`estimated`).
- Regras comuns: papel inexistente → `SourceFailure` (`ticker_not_found` + dica); ticker existe mas não tem opção → lista vazia + motivo; data sem sessão → `no_session`; unidades da spec (R$ na borda, IV/RV em % a.a., gregas como gravadas, `t` em du/252).
- **Contagem de linhas**: o MCP nunca devolve > 60 linhas; se a consulta tiver mais, trunque e diga `total`/`returned`/`truncated`.
