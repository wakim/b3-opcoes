### 4.2 Implementação paralela, somente após fechar o contrato

Depois dos dois relatórios, o orquestrador fixa o contrato mínimo:

```ts
type LanguageMode = 'expert' | 'leigo'

// API conceitual do contexto; os nomes finais podem seguir o estilo do projeto.
useLanguage(): {
  mode: LanguageMode
  setMode(mode: LanguageMode): void
}

type PresentationKey = string // união derivada das chaves do dicionário
useCopy(key: PresentationKey, variant?: string): {
  label: string
  help?: string
  glossaryKey?: string
}
```

Regras desse contrato:

- um dicionário único de apresentação, com rótulo `expert`, rótulo `leigo`, ajuda Expert existente quando houver, ajuda Leigo curta e `glossaryKey` quando houver;
- variantes nomeadas no dicionário são permitidas para preservar rótulos e ajudas Expert já diferentes por superfície;
- nenhum `if (mode === 'leigo')` espalhado por rotas, gráficos ou formulários;
- valores enviados à API permanecem os mesmos (`iv_atm_30d`, `vrp`, etc.); só o rótulo visível muda;
- `OpenMetric`/`ModalTarget` ganham `term?: PresentationKey` de forma opcional e retrocompatível; `field`, `label` e `value` continuam aceitos;
- `glossaryKey`/slug não depende do idioma;
- definições completas não são copiadas para o dicionário.

Antes de disparar implementação, escreva uma matriz **arquivo → dono**. Nenhum arquivo pode ter dois dones.

Use dois `general` com o modelo Hy4 flash Free, em paralelo:

## 5. Implementação

### F9.1 — preferência global

- Crie `frontend/src/lib/language.tsx` com `LanguageProvider` e `useLanguage`, e `frontend/src/components/LanguageToggle.tsx` para o seletor.
- Use a chave `b3o:language`, com valores exatos `expert` e `leigo`.

- Persistência deve sobreviver a reload, atualização do PWA e uso offline.
- O seletor alterna sem reload e sem invalidar/refazer queries de dados.
- Coloque o provider acima de `AppShell`; não coloque o `useLanguage` no mesmo componente que retorna o provider.
- Coloque o seletor no header, junto do `Stamp`. Reutilize o `ToggleGroup` já validado, adaptado para seleção única; `onValueChange` deve ignorar `''`, mantendo uma opção sempre selecionada. O `NativeSelect` existente também é aceitável. **Não adote o Radix Select**: o piloto da F8.5.4 falhou o critério visual.

### F9.2 — dicionário único

- No Leigo, use o termo expandido antes da sigla: “Volatilidade implícita (IV)”, “Volatilidade realizada (RV)”, “Prêmio de volatilidade (VRP)”, “Delta (Δ)”, “Lucro/prejuízo (P&L)”, “No dinheiro (ATM)”.
- Cubra no mínimo: IV/RV/VRP, Δ/Gamma/Theta/Vega, RR25/BFLY25, ATM, z-score, posição da volatilidade, P&L, forward, DF, OI, strike/preço de exercício, spread, bid/ask, call/put, europeia/americana, perna, payoff, breakeven, estruturas, D-1/D-n, EOD, append-only, flags, códigos de exclusão, ações e mensagens recorrentes. Não acrescente uma métrica que hoje não aparece só para traduzi-la.

- Reaproveite `metricKeys.ts`, `HelpTip`, `InfoTip` e `MetricModal`.
- Mantenha `const KEYS` em `metricKeys.ts` com a mesma forma sintática e mantenha os literais `field="..."`, `openMetric('...')` e `onMetric('...')`: o `glossary-coverage.mjs` lê texto, não tipos.

- Não troque `HelpTip` pelo wrapper Radix que já falhou no toque; preserve o painel inferior mobile e a supressão do clique sintético.

- No Expert, preserve as ajudas atuais; onde hoje existe fallback `O que é ${label}`, represente-o no dicionário em vez de sintetizar no componente.

- Nenhuma informação essencial depende exclusivamente de hover: o rótulo expandido é visível e a ficha completa tem acionável por teclado/toque.
- Alvos ≥ 44 px nos dois eixos.
- Em tabelas, rótulos longos podem quebrar linha dentro da região de scroll; não reduzam a tipografia abaixo dos tokens aprovados nem criem overflow fora do `.table-wrap`.

## 8. Comandos de regressão

Rode dentro dos containers. O exemplo usa **8093**; substitua pela porta livre escolhida. A cobertura só roda depois que a app isolada estiver no ar:

```powershell
podman compose config --quiet
podman compose run --rm test ruff check src
podman compose run --rm test b3o health

New-Item -ItemType Directory -Force data/out | Out-Null
podman compose --profile build run --rm web sh -c "npm ci >&2 && npm run build >&2 && find dist -type f -print0 | sort -z | xargs -0 sha256sum" | Out-File -Encoding utf8 data/out/f9-build-1.sha256
podman compose --profile build run --rm web sh -c "npm ci >&2 && npm run build >&2 && find dist -type f -print0 | sort -z | xargs -0 sha256sum" | Out-File -Encoding utf8 data/out/f9-build-2.sha256
Compare-Object (Get-Content data/out/f9-build-1.sha256) (Get-Content data/out/f9-build-2.sha256)
podman compose --profile build run --rm web npm run check

$env:B3_APP_PORT="8093"
podman compose -p b3o-f9 build app
podman compose -p b3o-f9 up -d app

$ready = $false
for ($i = 0; $i -lt 60 -and -not $ready; $i++) {
  try {
    $response = Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8093/api/health?probe=1" -TimeoutSec 2
    $ready = $response.StatusCode -eq 200
  } catch { $ready = $false }
  if (-not $ready) { Start-Sleep -Seconds 1 }
}
if (-not $ready) { throw "a app F9 não ficou pronta em 60s" }

podman compose --profile build run --rm -e B3_HTTP_URL=http://host.containers.internal:8093 web npm run coverage
podman compose run --rm -e B3_MCP_URL=http://host.containers.internal:8093/mcp -e B3_HTTP_URL=http://host.containers.internal:8093 test python scripts/mcp_smoke.py
podman compose run --rm -e B3_MCP_URL=http://host.containers.internal:8093/mcp -e B3_HTTP_URL=http://host.containers.internal:8093 test python scripts/structure_smoke.py
podman compose run --rm -e B3_HTTP_URL=http://host.containers.internal:8093 test python scripts/liquid_smoke.py
podman compose run --rm test python scripts/positions_smoke.py
podman compose run --rm test python scripts/journal_smoke.py
```

`Compare-Object` sem saída significa builds idênticas. Se `ruff` falhar por dívida preexistente, registre o baseline e **não edite `backend/`** para resolver na F9. `positions_smoke.py` e `journal_smoke.py` precisam manter isolamento PostgreSQL próprio. Não leia nem imprima `.env`/`APP_TOKEN`.

Para medir o lake, execute o mesmo comando antes e depois da prova de UI, salvando em arquivos diferentes:

```powershell
Get-ChildItem data -Recurse -File |
  Where-Object { $_.FullName -notlike '*\data\out\*' } |
  Sort-Object FullName |
  ForEach-Object { "{0}  {1}" -f (Get-FileHash $_.FullName -Algorithm SHA256).Hash, $_.FullName } |
  Out-File -Encoding utf8 data/out/f9-lake-before.sha256
```

Repita com `f9-lake-after.sha256` e compare os dois arquivos. Ao final, encerre somente o projeto isolado com `podman compose -p b3o-f9 down`; não use `-v` no volume oficial.

Não trate o aviso de chunk > 500 KB nem os avisos `MODULE_LEVEL_DIRECTIVE` do Vite/Rolldown como falha. Registre vulnerabilidades/dependências sem alterá-las fora do escopo.
