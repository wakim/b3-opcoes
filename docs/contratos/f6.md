# Contrato F6 — Posições e Carteira

## 1. Persistência

- O journal é **PostgreSQL + SQLAlchemy Core + Alembic**, separado do lago Parquet/DuckDB.
  Abertura insere `position`, `position_leg`, evento `open` e `prediction` opcional. Fechamento
  insere somente evento `close`; status/`closed_session` são derivados do evento.
- Triggers bloqueiam `UPDATE`, `DELETE` e `TRUNCATE` nas quatro tabelas do diário. Índices únicos parciais
  garantem no máximo um `open` e um `close` por posição; o fechamento usa lock transacional.
- `DATABASE_URL` vem do Compose para `app`, `dev` e `test`. O banco fica no volume nomeado
  `b3o-postgres`, sem porta publicada, montado em `/var/lib/postgresql` (PostgreSQL 18+).
- A migration inicial única é `backend/migrations/versions/0001_f6_initial.py`. Alembic é o único
  caminho de criação/evolução do schema; GET não cria schema, arquivo ou posição.

## 2. Autenticação

- Leitura (`GET /api/positions*`) liberada na tailnet.
- Escrita (`POST /api/positions*`) exige `X-App-Token` igual a `APP_TOKEN`.
- Token ausente no servidor → `503 app_token_missing`; token inválido → `401 unauthorized`.
- O token fica no `localStorage` do PWA após a primeira digitação; nunca é logado.
- A dependência de autenticação roda antes do parse do JSON; token não ASCII inválido → 401, não 500.

## 3. API

Envelope canônico `{as_of_session, model_version, data, meta}`; listas ≤ 60 e resposta ≤ 200 KB.

### `POST /api/positions`

Corpo:

```json
{
  "client_position_id": "uuid4-estavel-no-rascunho",
  "underlying": "PETR4",
  "date": "2026-11-18",
  "notes": null,
  "capital_limit_brl": 5000.0,
  "legs": [
    {"kind": "stock", "ticker": "PETR4", "side": "long", "quantity": 100},
    {"kind": "option", "ticker": "PETRL44", "side": "short", "quantity": 100}
  ],
  "prediction": {
    "metric": "vrp",
    "operator": ">=",
    "value": 0.0,
    "horizon_sessions": 5,
    "evaluate_on": "2026-11-26"
  }
}
```

- `quantity` é número de ações; nada é multiplicado por 100.
- Preço de entrada, strike, IV e delta vêm do lake da sessão.
- `kind` é derivado das pernas.
- `client_position_id` é opcional. Repetir o mesmo UUID com o mesmo corpo devolve a posição existente; mesmo UUID com outro corpo → `409 position_id_conflict`. O PWA persiste rascunho + UUID em `sessionStorage` até sucesso ou descarte explícito, sem guardar o token.
- Retorna o mesmo `PositionDetail`. Se o payoff não couber em 200 KB, ele é omitido com `payoff_truncated` + `meta.note`, nunca exibido parcial.

### `POST /api/positions/{id}/close`

Corpo `{ "date": "2026-11-23" }` (default última sessão). Marca as pernas pelo `mid`/fechamento da
sessão, grava evento `close` com snapshot completo (marcas, gregas, strike, spot, IV e P&L) e retorna
`PositionDetail` realizado. Segundo fechamento, inclusive concorrente, → `409 position_closed`.
Sem marca positiva em todas as pernas, o fechamento é `400 bad_request`.

## 4. Cálculos e flags

- `pnl_brl = Σ sign × qty × (mark − entry)`; fechada usa o mark do fechamento.
- `pnl_pct = pnl_brl / capital_committed_brl`; sem capital → `null`.
- Gregas líquidas: ação Δ=1; opção usa gregas gravadas. Δ em R$ = Δ × qty × spot.
- Marca ausente → P&L/gregas agregados `null` + flag, nunca parcial silencioso.
- Flags: `near_expiry` (≤ 5 sessões), `itm` (|Δ|>0,85), `delta_drift` (>0,25),
  `event_in_window` (evento/vencimento ≤ 5 sessões), `thesis_failed`, `capital_over`,
  `one_sided`, `mark_missing`, `gregas_parciais`, `unbounded_loss`, `payoff_unavailable`,
  `payoff_truncated`, `close_snapshot_missing`.
- Payoff no vencimento usa preços de entrada; nenhum número nasce no frontend.

## 5. MCP

Tool read-only `positions(date=None, max_rows=20, offset=0)` com o mesmo payload e paginação de
`GET /api/positions`. Não existe tool de escrita. `screen` e `structure_eval` orientam o agente a
consultar `positions` antes de comentar exposição.

## 6. Comportamento da UI

- Leitura não exige token. No 401 da abertura, o formulário/rascunho permanece e apenas o token é limpo; no 401 do fechamento, a data escolhida permanece.
- No 409 `position_closed`, posição e carteira são recarregadas.
- Durante POST pendente, o diálogo bloqueia Escape/backdrop/cancelar e todos os campos.
- `/api/positions*` é `NetworkOnly` no service worker: GET velho não sobrescreve uma escrita confirmada.
