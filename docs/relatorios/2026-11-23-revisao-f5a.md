## 3. Ressalvas — status final

| ID | Gravidade | Status | Resumo |
|---|---|---|---|
| A1 | Alta | **FECHADA** (`211dece`) | Provider envolvia o próprio consumidor → SPA não renderizava |
| M1 | Média | **FECHADA** (`211dece`) | Contador da cadeia usava `meta.returned` (recorte) |
| N1 | Nit | **RESOLVIDA** | Imagem reconstruída após o source final |
| B1 | Baixa | Pendência F5-B (não bloqueante) | `staleTime` 1 h de tickers sem consumidor de UI |
| B2 | Baixa | Pendência F5-B (não bloqueante) | `plain()` não remove `>` / `---` / links Markdown |
| N2 | Nit | Observação nova | Build do bind e build da imagem divergem no CSS por varredura do `dist` antigo |

**A1 — FECHADA.** `RootLayout` agora só retorna `<QueryClientProvider client={queryClient}><AppShell /></QueryClientProvider>`; `AppShell` é filho e contém o `useQuery` do carimbo. Contexto de provider alcança descendentes na árvore de fibers — o padrão que antes lançava `No QueryClient set, use QueryClientProvider to set one` agora renderiza (`FIXED RENDER: <div>ok status=pending</div>`). Navegador sem erro de console, carimbo e tela Hoje presentes. Não há mais bloqueio para a F5-B.

**M1 — FECHADA.** `t.$ticker.tsx` lê `chain.data?.meta?.total`. Agora o número reflete o total após filtro (e não o recorte de 20 linhas), coerente com o `meta` do envelope e com o contrato "nº de linhas".

**N1 — RESOLVIDA.** Imagem `app` reconstruída com o source final. Conferido: o JS do container (`index-BDwkbGEG.js`, SHA-256 `9272ac0196cc…`) é idêntico ao de um build fresco do source atual sem `dist` prévio. Smokes 53/53 e 93/93 no app final.

**B1 — PENDÊNCIA F5-B.** ADR-032 declara `staleTime` 1 h para glossário e tickers; só `/api/glossary` tem consumidor nesta sessão. O §4.5 do contrato F5-A não prevê UI de busca — implementar na F5-B ou ajustar o ADR. Não é defeito de código entregue.

**B2 — PENDÊNCIA F5-B.** `aprender.tsx` / `plain()` remove `**` e crases, mas não blockquote (`>`), regras (`---`) nem links `[texto](url)`. Nos 30 verbetes reais nada disso aparece (o único com `>` é justamente o "Fora do produto", omitido). Revisar se o glossário ganhar verbetes com esses elementos.

**N2 — OBSERVAÇÃO (nit).** O CSS do build no bind (11.165 B, `index-CtxYpLhL.css`) difere do CSS da imagem (8.250 B, `index-DB9lSv3P.css`) porque o Tailwind v4 varre arquivos do projeto e, no bind, encontra um `frontend/dist` prévio; no build da imagem o `.dockerignore` o exclui. Reprovado em container descartável: com `dist` removido, o build gera exatamente os hashes da imagem (`index-BDwkbGEG.js` + `index-DB9lSv3P.css`, SHA-256 idênticos). O conteúdo extra é CSS inofensivo e as duas builds seguidas no bind estabilizam; a imagem é o artefato canônico. Não afeta funcionalidade, mas vale registrar para não confundir hashes de ambientes diferentes.

**Ressalva da rodada 1 — FECHADA:** no início, F5.2/F5.3/F5.4 estavam no working tree; foram commitados e enviados (`bd94de2`, `d7cf6dc`, `53226c6`, `211dece`). `git log origin/main..HEAD` vazio e `git diff` dos congelados vazio.
